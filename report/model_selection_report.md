## 1. 요약

* **결론**: 모델 하나를 처음부터 고르지 않고, **데이터·라벨 확보 수준에 맞춰 3단계로 확장**합니다.

  | 단계 | 모델 | 목적 | 필요한 라벨 |
  | :--- | :--- | :--- | :--- |
  | **1차** | **PatchCore** (비지도 이상 탐지) | 이 데이터로 양/불량 구분이 가능한지 **타당성 확인** | 양/불량만 (학습은 정상만 사용) |
  | **2차** | **YOLO** (지도 학습 검출) | 불량 위치를 직접 찾는 **검출 성능 확보** | `defect` 단일 클래스 박스 |
  | **3차** | **YOLO 다중 클래스** | 찍힘·균열 등 **불량 유형 구분** | 유형별 박스 |

* **1차를 PatchCore로 하는 이유**: 정상 이미지만으로 학습하고 라벨링이 필요 없으며, 역전파 학습이 없어 빠릅니다. PRD의 "소량 데이터", "24시간 내 재학습", "품목마다 다른 불량 유형" 조건에 가장 잘 맞고, 이후 YOLO 라벨링을 돕는 히트맵도 만들어 줍니다.
* **YOLO 버전**: 특정 버전에 묶지 않고 **성능과 학습 시간**으로 고릅니다 (2차에서 nano급 후보끼리 비교).
* **검증의 핵심 한계**: PRD 목표(미검률 ≤ 0.01%)를 통계적으로 증명하려면 불량 약 30,000장이 필요합니다. 현재 평가용 불량은 십여 장이므로, 이 PoC는 **"목표 달성 증명"이 아니라 "타당성 확인과 실데이터 확보 규모 산정"** 을 목표로 합니다 (7장).

## 4. 모델 후보 비교

| 후보 | 방식 | 필요한 데이터 | 위치 정보 | 처음 보는 불량 | 학습 부담 | PoC 판단 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **PatchCore** | 정상 패치 특징 저장 후 거리 비교 | 정상만 | 히트맵 | **가능** | 낮음 (역전파 없음) | **1차 채택** |
| FastFlow | 정상 분포를 생성 모델로 학습 | 정상만 | 히트맵 | 가능 | 중간 (에폭 학습) | PatchCore 미달 시 대안 |
| YOLO 분류 (`-cls`) | 정상/불량 이미지 분류 | 양/불량 라벨 | 없음 | 어려움 | 낮음 | 2차 비교 기준선 |
| **YOLO 검출** | 결함 박스 검출 | 박스 라벨 | 박스 | 어려움 | 중간 | **2·3차 채택** |
| MobileNetV4 / EfficientNet-Lite | 이미지 분류 | 양/불량 라벨 | 없음 | 어려움 | 낮음 | 위치 정보가 없어 제외 |

### 4.1 PatchCore 동작 원리 (YOLO와의 차이)
1. ImageNet으로 사전 학습된 CNN에 정상 이미지를 통과시켜, 이미지의 작은 조각(패치)별 특징 벡터를 뽑습니다.
2. 이 벡터들 중 대표만 골라 **"정상 패치 메모리"** 로 저장합니다 (코어셋 샘플링). 이것이 학습의 전부이며, 가중치 업데이트(역전파)가 없습니다.
3. 검사할 때는 각 패치가 메모리 속 가장 가까운 정상 패치와 얼마나 먼지 계산합니다. 가장 먼 값이 **이미지 이상 점수**, 패치별 값을 펼친 것이 **결함 위치 히트맵**입니다.
4. 이상 점수가 **임계값**을 넘으면 불량으로 판정합니다. 임계값은 검증 데이터로 정합니다.

| 비교 | YOLO | PatchCore |
| :--- | :--- | :--- |
| 학습 데이터 | 정상 + 불량 (+ 박스) | 정상만 |
| 학습 방식 | 에폭 반복, 역전파 | 특징 추출 1회 + 메모리 저장 |
| 출력 | 클래스·박스·신뢰도 | 이상 점수·히트맵 |
| 하이퍼파라미터 | 에폭, 학습률, 증강 등 | 백본 레이어, 코어셋 비율, 임계값 |
| 구현 | Ultralytics | `anomalib` 라이브러리 또는 PyTorch 직접 구현 |

### 4.2 단계적 전략을 택한 이유
* **위험을 단계별로 줄임**: 1차에서 "이 데이터·전처리로 정상과 불량이 구분되는가"를 라벨링 비용 없이 먼저 확인합니다. 구분이 안 되면 YOLO로 가도 결과가 나쁠 가능성이 높으므로, 데이터부터 다시 봅니다.
* **앞 단계 산출물이 다음 단계 입력**: 1차 히트맵 → 2차 박스 라벨 초안. 2차 박스 → 3차 유형 라벨의 바탕.
* **운영 구조로 이어짐**: 최종적으로 PatchCore(새 품목·처음 보는 불량 대응)와 YOLO(알려진 불량의 정밀 검출·유형 분류)를 함께 운영하는 구조를 검토할 수 있습니다.

## 5. 공통 실험 설계

세 단계 모두 아래 설계를 공유해야 결과를 서로 비교할 수 있습니다.

### 5.1 데이터 정제와 분할
* **정제**: 완전 중복 제거, 도금·녹 너트 제외, 유사 이미지는 같은 `group_id`로 묶음 (`data_preprocessing.md` A1~A2).
* **분할**: `group_id` 단위로 학습 70 / 검증 15 / 평가 15. 클래스 × 흐림 여부 × 원거리 여부 비율을 층화.
* **평가 세트 고정**: 1차에서 만든 평가 세트를 2·3차에서도 그대로 사용. 평가 세트는 학습·임계값 결정에 절대 쓰지 않음.
* **모델별 사용 범위**

  | 세트 | PatchCore (1차) | YOLO (2·3차) |
  | :--- | :--- | :--- |
  | 학습 | 정상만 | 정상(배경 이미지) + 불량(박스) |
  | 검증 | 정상 + 불량 → 임계값 결정 | 정상 + 불량 → 조기 종료·신뢰도 임계값 |
  | 평가 | 정상 + 불량 (공통) | 정상 + 불량 (공통) |

### 5.2 전처리
* `data_preprocessing.md`의 B1~B8 파이프라인을 학습·추론에 동일하게 적용.
* 입력 크기: PatchCore 256×256 (정렬 크롭), YOLO 640×640 (2차에서 크롭 입력과 원본 입력 비교).

### 5.3 지표

| 구분 | 지표 | PRD 연결 |
| :--- | :--- | :--- |
| 판정 성능 | 이미지 단위 AUROC | 임계값과 무관한 분리 능력 |
| | 임계값 기준 **미검률(FNR)**, **과검률(FPR)**, F1 | 3. 성공 지표, 2. 시나리오 3단계 |
| 위치 | 결함 위치 적중률 (히트맵 최대점 또는 박스가 실제 결함과 겹치는 비율) | 결함 좌표 추출 |
| 편향 | 흐린/선명, 원거리/근거리 그룹별 AUROC·FNR·FPR | 데이터 편향 점검 |
| 효율 | 학습 시간, 이미지당 추론 시간(전처리 포함), 모델 크기 | 24시간 주기, 35ms, 50~100MB |

### 5.4 임계값 결정 원칙
* PRD는 미검률(0.01%)을 과검률(0.5%)보다 훨씬 엄격하게 요구합니다. 따라서 **검증 세트 불량을 모두 잡는 임계값**을 기본으로 하고, 그때의 과검률을 보고합니다.
* 보조로 F1 최대 임계값도 함께 보고해 차이를 비교합니다.

### 5.5 신뢰구간 보고
* 평가 표본이 적으므로 미검률·과검률은 **점추정과 95% 신뢰구간(Clopper-Pearson)** 을 함께 보고합니다. 예: 불량 13장 중 미검 0장이어도 미검률의 95% 신뢰구간 상한은 약 25%입니다.

### 5.6 실행 환경
* Google Colab (GPU), Drive 마운트. 실험 기록은 MLflow(로컬 파일 저장)로 남겨 PRD 스택과 맞춤.
* 지연시간은 Colab GPU 측정값이며, 엣지 PC(RTX + TensorRT) 실측은 별도로 필요합니다.

## 6. 단계별 계획

### 6.1 1차 — PatchCore 타당성 확인 (Feasibility Check)

**목적**: 라벨링 없이, 이 데이터와 전처리로 정상과 불량이 구분되는지 확인합니다.

**학습 방법**
1. 학습 세트의 정상 이미지(무처리 너트)를 B1~B8 전처리 → 256×256.
2. ImageNet 사전 학습 백본(WideResNet-50 계열)의 중간 레이어 특징 추출.
3. 코어셋 샘플링으로 메모리 크기 축소 → 정상 패치 메모리 저장.
4. 검증 세트로 임계값 결정 (5.4).

**실험 변형** (같은 평가 세트로 비교)

| 실험 | 내용 | 확인할 것 |
| :--- | :--- | :--- |
| P-1 기본 | 원본 전처리만 | 기준 성능 |
| P-2 흐림 대응 | 학습용 정상 이미지에 축소→재확대 열화 증강 추가 | 흐린 정상의 과검이 줄어드는가 |
| P-3 경량화 | 백본 레이어·코어셋 비율 축소, FP16 | 성능 손실 대비 크기·속도 이득 |

**통과 기준 (제안, 합의 필요)**
* 평가 세트 이미지 AUROC ≥ 0.90
* 흐린/선명 그룹 간 AUROC 차이 ≤ 0.10 (편향이 성능을 좌우하지 않음)
* 불량 히트맵 최대점이 실제 결함 부위에 위치하는 비율 ≥ 70% (육안 검수)
* 전처리 + 추론 ≤ 35ms (Colab GPU 기준 참고값)

**산출물**: 이상 점수 분포 그래프, 히트맵 샘플, 결과표(6.4), 불량 이미지별 히트맵(2차 라벨 초안용).

**미달 시 조치**: FastFlow 등 대안 이상 탐지 모델 비교 → 그래도 미달이면 데이터 문제(편향·왜곡)로 보고 실데이터 확보를 우선합니다.

### 6.2 2차 — YOLO 불량 검출

**목적**: 불량 위치를 박스로 적극적으로 검출하고, 1차 PatchCore 대비 성능을 비교합니다.

**라벨링** (양/불량 → `defect` 단일 클래스 박스)
1. 1차 히트맵에서 이상 영역을 잘라 **박스 초안 자동 생성**.
2. 사람이 초안을 검수·수정 (폐쇄망 전제이므로 Label Studio, CVAT 등 로컬 도구 사용).
3. 박스는 **원본 640×640 좌표**로 저장. 전처리 크롭 입력을 쓸 때는 전처리의 변환 행렬로 좌표 변환.
4. 정상 이미지는 라벨 파일 없이 **배경 이미지**로 학습에 포함 (오검 감소).
5. 박스 기준 문서화: 찍힘은 결손 부위만, 긴 균열은 하나의 박스, 녹·균열 동반 시 균열 기준.

**학습 방법**
* COCO 사전 학습 가중치에서 파인튜닝. nano급 모델끼리 비교해 **성능과 학습 시간**으로 버전 선택.
* 증강: 회전·뒤집기, 밝기·대비, **정상·불량 모두에 같은 확률로 흐림 열화** (흐림 편향 차단).
* 기준선으로 같은 데이터에 **YOLO 분류(`-cls`)** 도 학습해 비교 (박스 라벨의 효과 확인).

**실험 변형**

| 실험 | 내용 | 확인할 것 |
| :--- | :--- | :--- |
| Y-1 | 원본 640 입력 | 기준 성능 |
| Y-2 | 전처리 크롭 입력 | 정렬·크기 정규화 효과 |
| Y-3 | 흐림 증강 on/off | 편향 감소 효과 |
| Y-4 | 분류 모델 (`-cls`) | 박스 라벨이 성능에 기여하는가 |

**통과 기준 (제안)**
* 평가 세트에서 1차 PatchCore 대비 **미검률이 같거나 낮고 과검률이 낮음**
* 흐린/선명 그룹 간 성능 차이가 1차보다 작음
* 학습 시간이 PRD 24시간 주기 안에 충분히 들어옴

**산출물**: 결과표(6.4), PatchCore와의 비교표, 박스 라벨 데이터셋(DVC 버전 관리).

## 7. 검증의 통계적 한계

오류가 0건일 때 95% 신뢰 상한은 약 3/n입니다 (rule of three). 이를 기준으로 PRD 목표를 증명하는 데 필요한 표본 수는 다음과 같습니다.

| PRD 목표 | 오류 0건으로 증명하려면 필요한 표본 | 현재 평가 세트 (예상) |
| :--- | :--- | :--- |
| 미검률 ≤ 0.01% | 불량 약 **30,000장** | 불량 약 13~15장 |
| 과검률 ≤ 0.5% | 정상 약 **600장** | 정상 약 15~20장 |

* 따라서 이번 PoC의 결론은 "PRD 목표 달성"이 아니라 **"모델이 구분 능력을 보이는가, 그리고 목표 검증에 실데이터가 얼마나 필요한가"** 로 제한합니다.
* 미검률 0.01%는 실제 운영에서 모델 하나로 증명하기 어려운 수준이므로, 운영 단계에서는 임계값을 보수적으로 두고 경계 점수 부품을 재검사하는 등 **공정 차원의 안전장치**도 함께 검토해야 합니다.
