## 1. 개요

이전 버전은 샘플 2장(`synth_defect_113`, `synth_non_defect_106`)을 기준으로 작성되었습니다. 이번 개정에서는 데이터셋 260장(불량·정상 각 130장)을 전수 분석하고, 현장 조사 체크리스트 기입 결과를 반영해 전략을 다시 세웠습니다.

전처리는 두 단계로 나눕니다.

| 단계 | 언제 | 목적 |
| :--- | :--- | :--- |
| **A. 데이터 정제 (오프라인)** | 학습 전 1회 | 중복·편향·도메인 혼재를 정리해 **모델이 결함이 아닌 다른 단서로 판별하지 못하게** 함 |
| **B. 엣지 전처리 (온라인)** | 학습·추론 공통, 매 프레임 | 촬영 조건 편차(크기·회전·밝기)를 줄여 **모델 입력을 일정하게** 맞춤 |

### 1.1 이전 가정과 전수 분석 결과 비교

| 항목 | 이전 가정 (샘플 2장) | 전수 분석 결과 | 전략 변경 |
| :--- | :--- | :--- | :--- |
| 배경 | 밝은 단색(~230) | 배경 밝기 118~255, 흰색·회색·연보라 혼재 | 밝기 정규화 단계 추가 (B2) |
| 부품 분리 | 밝은 배경 대비로 Otsu 이진화가 쉬움 | **밝은 금속 면이 배경과 같은 밝기라 Otsu가 약 25% 이미지에서 부품 일부만 잡음** | 그래디언트 기반 ROI 검출로 교체 (B3) |
| 부품 크기 | 화면 중앙 고정 크기 | 화면 면적 6%~63%, 약 10배 차이 | 크롭 후 크기 정규화 추가 (B5) |
| 회전 | 30~45° 기울어짐 | 0~360° 임의 | 회전 정렬 유지 + 90° 대칭 처리 (B4) |
| 결함 크기 | 15~35px | 일반 거리 30~120px, 균열 폭 2~5px, 소형 촬영 노치 5~15px | 미세 균열 보호를 위해 메디안 필터 기본 제외 (B7) |
| 블러 | 없음 | 모션 블러는 없으나 **업스케일 흐림이 불량 68% / 정상 26%** | 디블러는 계속 제외, 대신 양 클래스 화질 균형화 (A4) |
| 품종 | 단일 | 불량 클래스에만 아연도금·녹 너트 혼재 | 도메인 분리, 1차 범위 축소 (A2) |

### 1.2 편향(Shortcut) 위험 실측

결함을 보지 않고 **이미지 전체 통계만으로** 정상/불량을 구분할 수 있는지 로지스틱 회귀로 확인했습니다 (5-fold 교차검증, 260장).

| 사용한 특징 | 정확도 |
| :--- | :--- |
| 선명도(라플라시안 분산)만 | 71.5% |
| 고주파 비율만 | 71.5% |
| 채도만 | 65.8% |
| 배경 밝기만 | 58.5% |
| 부품 면적만 | 53.5% |
| 위 특징 전부 | **75.4%** |

결함과 무관한 단서만으로 75%를 맞출 수 있습니다. 그대로 학습하면 모델이 "흐리거나 색이 있으면 불량"이라고 배울 수 있으므로, **A단계의 목표는 이 수치를 50%(무작위 수준)에 가깝게 낮추는 것**입니다.

**추가 실측 — 범위 축소·전처리만으로는 편향이 줄지 않음**

| 조건 | 전체 특징 정확도 |
| :--- | :--- |
| 원본 260장 | 75.4% |
| `material = plain`만 (A2 적용) | **77.6%** |
| B1~B7 전처리 후 | **80.0%** |
| B1~B7 전처리 후 + `material = plain` | **81.7%** |

* 도금·녹 이미지를 빼도(A2) 흐림·크기 차이는 그대로 남아 정확도가 오히려 올라갑니다.
* 전처리 후 크롭에서 잰 통계는 실제 결함 정보(노치로 인한 윤곽 변화 등)도 일부 담고 있어 순수한 편향 수치는 아닙니다. 다만 결함과 무관한 **고주파 비율(흐림)만으로도 68~71%** 가 나오므로 흐림 편향은 확실히 남아 있습니다.
* 결론: 편향 제거의 핵심은 범위 축소나 엣지 전처리가 아니라 **A4 화질 균형화(양 클래스 동일 열화 증강)** 와 **실데이터 확보**입니다. 60% 목표는 아직 달성되지 않았습니다.

## 2. A단계 — 데이터 정제 (오프라인)

### A1. 중복 제거 및 그룹 ID 부여
* **근거**: MD5 기준 완전 동일 파일 8그룹(9장 중복). 지각 해시(pHash) 거리 6 이하 유사 이미지까지 묶으면 고유 이미지는 불량 약 98장, 정상 약 104장.
* **처리**:
  * 완전 중복은 1장만 남기고 제거.
  * 유사 이미지는 삭제하지 않고 **같은 그룹 ID**를 부여 → A6 데이터 분할에서 한쪽으로 묶음.

### A2. 도메인 태깅 및 1차 학습 범위 축소
* **근거**: 아연도금(약 22장)·녹+균열(약 19장) 너트는 불량 클래스에만 있고 정상 데이터가 0장. 이대로 쓰면 "도금/녹 = 불량"을 학습함.
* **처리**: 이미지별로 아래 태그를 기록 (메타데이터 CSV).

  | 태그 | 값 |
  | :--- | :--- |
  | `material` | `plain` / `zinc` / `rust` |
  | `scale` | `normal` / `small` (부품 면적 12% 미만) |
  | `blur` | `sharp` / `blurry` (라플라시안 분산 30 미만) |
  | `aspect_distorted` | 외곽 박스 장단변 비 1.3 초과 여부 |
  | `group_id` | A1 중복 그룹 |

* **1차 학습 범위**: `material = plain`인 정상/불량만 사용. `zinc`, `rust`는 해당 품종 정상 데이터를 확보할 때까지 별도 보관 (평가에도 쓰지 않음).

### A3. 형상 왜곡 이미지
* **근거**: 외곽 박스 장단변 비가 1.3을 넘는 이미지가 114장(불량 44 / 정상 70). 타원형 나사 구멍도 다수.
* **처리**: 태그만 달고 **제외는 보류**. 실제 너트가 직사각형인지 현장 규격으로 확인한 뒤 결정 (체크리스트 1-4).

### A4. 화질 균형화 (흐림 편향 제거)
* **근거**: 흐린 이미지 비율이 불량 68% / 정상 26%로 차이가 큼. 흐림은 업스케일 형태라 복원(디블러)으로는 정보가 돌아오지 않음.
* **처리**: 흐린 불량을 버리면 불량 데이터가 크게 줄어들므로, 반대로 **정상 이미지에도 같은 열화를 적용**함.
  * 학습 시 양 클래스 모두에 무작위 "축소 → 재확대"(배율 0.3~0.6) 증강을 같은 확률로 적용 (4장 참고).
  * 검증·평가 세트는 열화 없이 원본 그대로 두되, `blur` 태그별 성능을 따로 집계.

### A5. 라벨 보강
* **이미지 단위 결함 유형** (전 불량 이미지): `chip`(찍힘·노치) / `crack` / `thread`(나사산 손상) / `dent` / `scratch`.
* **결함 위치 박스**: YOLO 학습에 필수. 1차 PatchCore는 정상 이미지만 쓰므로, 박스 라벨은 2차 단계에서 진행.
* **경계 사례 표시**: 결함이 거의 보이지 않는 불량(예: `synth_defect_7, 20, 25, 87, 102`)은 `ambiguous` 플래그 → 현장 판정 기준 확인 후 확정.

### A6. 데이터 분할
* **그룹 단위 분할**: 같은 `group_id`는 반드시 같은 세트로 (유사 이미지가 학습·평가에 나뉘면 성능이 부풀려짐).
* **층화**: 클래스 × `scale` × `blur` 비율을 각 세트에서 비슷하게 유지.
* **비율**: 학습 70 / 검증 15 / 평가 15. 평가 세트는 고정 후 변경 금지.
* **검증 기준**: 정제 후 데이터로 1.2절 편향 테스트를 다시 돌려 정확도가 **60% 이하**인지 확인.

## 3. B단계 — 엣지 전처리 파이프라인 (온라인)

학습과 추론에 **같은 코드**를 사용합니다.

```
입력(640×640 RGB)
 → B1 그레이스케일
 → B2 배경 밝기 정규화
 → B3 ROI 검출 (그래디언트 + 볼록 껍질)
 → B4 회전 정렬
 → B5 크롭 + 크기 정규화
 → B6 배경색 패딩
 → B7 대비 보정 (약한 CLAHE)
 → B8 정규화 → 모델 입력
```

### B1. 그레이스케일 변환
* **근거**: 평균 채도 약 3으로 사실상 흑백. 색 정보는 녹·도금 구분에만 쓰이는데, 이 품종은 1차 범위에서 제외(A2).
* **처리**: 1채널 변환. 채널을 줄여 연산·메모리도 1/3로 감소.

### B2. 배경 밝기 정규화
* **근거**: 배경 밝기 118~255. 같은 부품도 촬영마다 밝기가 달라짐.
* **처리**: 화면 테두리 띠(폭 20px)의 밝기 중앙값을 배경 밝기로 추정하고, 이 값이 **220**이 되도록 전체 밝기를 비례 조정. 부품이 테두리에 닿는 근접 촬영에서도 중앙값을 쓰면 크게 흔들리지 않음.

### B3. ROI 검출 — 그래디언트 + 볼록 껍질 (Otsu 대체)
* **근거**: 기존 Otsu 이진화는 밝은 금속 면을 배경으로 분류해, 260장 중 64장(약 25%)에서 부품 윤곽이 깨짐 (대부분 근접 촬영된 밝은 회색 너트).
* **처리**:
  1. 1/2 축소(320×320) 후 5×5 가우시안 블러.
  2. Sobel 그래디언트 크기 계산.
  3. 임계값 = 테두리 그래디언트 중앙값 × 4 (12~60 범위로 제한). 배경이 매끈하다는 점을 이용한 적응형 기준.
  4. 엣지를 9×9로 팽창시켜 부품 엣지끼리 이어 붙인 뒤 **가장 큰 덩어리만** 채택 (원거리 소형 촬영에서 배경의 점·잡티가 ROI에 섞이는 문제 방지).
  5. 채택된 엣지 점의 **볼록 껍질(Convex Hull)** = 부품 영역.
* **검증 결과 (개발 PC, Python)**: 260장 모두 ROI 반환, 처리 시간 중앙값 2.5ms / 95백분위 3.7ms. 육안 확인 시 대부분 외곽에 잘 맞음.
  * 4번 단계 추가 전에는 소형 너트(`synth_defect_14, 41, 114` 등)에서 ROI가 부품보다 훨씬 크게 잡혀 크롭·정렬이 틀어졌으나, 추가 후 해결됨.
* **알려진 한계**:
  * 연보라 배경에 압축 블록 노이즈가 있는 이미지(`synth_defect_2`)는 배경 노이즈까지 잡혀 ROI가 화면 대부분(약 640×516)으로 커짐. 면적 비율이 90% 미만이라 **안전장치에도 걸리지 않음** → 배경 노이즈 대응은 실데이터 배경 확인 후 보완.
  * 부품이 화면을 가득 채운 경우 테두리가 부품이라 B2 배경 추정이 어긋나고, 회전 후 패딩 영역(220)과 원래 배경 사이에 밝기 경계가 보임 (예: `synth_defect_86`).
  * 진한 그림자가 있는 경우(`synth_non_defect_99, 106`) 그림자 일부가 ROI에 포함됨 → 여백 처리로 흡수.
  * 엣지 PC(C++/TensorRT 환경)에서는 처리 시간을 다시 측정해야 함.
* **안전장치**: ROI 면적이 화면의 90% 이상 또는 8% 미만이면 `roi_fail` 로그를 남기고 원본 전체를 사용.

### B4. 회전 정렬
* **근거**: 0~360° 임의 회전.
* **처리**: B3 볼록 껍질의 최소 회전 사각형(`minAreaRect`) 각도로 수평 정렬(`warpAffine`).
* **주의**: 사각 너트는 90° 대칭이라 정렬 후에도 0/90/180/270° 중 하나로 남음. 이 남은 차이는 학습 증강(90° 회전·뒤집기)으로 흡수.

### B5. 크롭 + 크기 정규화
* **근거**: 부품 크기가 약 10배 차이. 크기 차이 자체가 정상/불량을 가르는 단서가 되지 않도록 해야 함 (원거리 소형 이미지가 불량 23장 / 정상 4장).
* **처리**: 정렬된 부품 박스 + 사방 10% 여백으로 크롭 → 고정 크기로 리사이즈.
  * PatchCore: **256×256**
  * YOLO(2차): 640×640
* **주의**: 원거리 소형 이미지는 부품 자체의 화소 수가 적어 256px로 맞추면 확대되므로 미세 결함이 흐려질 수 있음. 원본 부품 크기를 `src_size` 메타로 남기고, ROI 한 변이 200px 미만이면 `low_res` 플래그 (현재 데이터셋은 ROI가 그림자를 포함해 잡혀 0장).

### B6. 배경색 패딩
* **근거**: 크롭·회전으로 생기는 빈 영역을 검정(0)이나 회색(114)으로 채우면 인공 경계가 생겨 결함으로 오인될 수 있음.
* **처리**: B2에서 맞춘 배경값 **220**으로 채움 (이전 전략 4 유지, 정규화 덕분에 고정값 사용 가능).

### B7. 대비 보정
* **처리**: CLAHE `clipLimit=1.5`, 타일 8×8을 약하게 적용해 챔퍼 그림자 속 파손 단면의 대비를 올림.
* **변경**: 이전의 3×3 메디안 필터는 **기본 제외**. 균열 폭이 2~5px이라 메디안 필터가 균열을 지울 수 있음. 가공 결 잡음 영향은 PatchCore 검증 결과를 보고 필요할 때만 다시 넣음 (비교 실험 항목).

### B8. 입력 정규화
* 0~1 실수 변환 후 학습 세트 정상 이미지의 평균·표준편차로 표준화. 통계값은 모델 패키지와 함께 배포.

### 제외한 단계
* **모션 디블러/샤프닝**: 한 방향으로 늘어진 모션 블러가 관찰되지 않음. 업스케일 흐림은 샤프닝으로 복원되지 않고 잡음만 키움.

## 4. 학습 시 증강 전략

| 증강 | 적용 | 이유 |
| :--- | :--- | :--- |
| 90° 회전 / 상하·좌우 뒤집기 | 양 클래스 | B4 정렬 후 남는 90° 대칭 흡수 |
| 잔여 회전 ±10° | 양 클래스 | 정렬 오차 흡수 |
| 축소→재확대 (배율 0.3~0.6), 확률 0.5 | **양 클래스 동일 확률** | 흐림 편향 제거 (A4) |
| 밝기 ±15%, 대비 ±10% | 양 클래스 | B2 정규화 후 남는 조명 차이 |
| 크기 ±10% | 양 클래스 | B5 크롭 오차 흡수 |
| ~~컷아웃 / 랜덤 지우기~~ | 사용 안 함 | 결함 부위를 지워 불량을 정상으로 만들 위험 |
| ~~강한 색상 변화~~ | 사용 안 함 | 그레이스케일 입력 |

PatchCore는 정상 이미지만으로 학습하므로, 증강은 정상 이미지의 변동 범위를 넓히는 용도로만 씁니다 (열화·밝기 증강 위주).

## 7. 전처리 검증 항목

| 항목 | 기준 | 방법 |
| :--- | :--- | :--- |
| ROI 검출 성공률 | ≥ 98% | 전 이미지 윤곽 오버레이 육안 검수, `roi_fail` 비율 |
| 회전 정렬 오차 | ≤ 5° (90° 대칭 제외) | 정렬 결과에서 외곽 각도 재측정. **실측: 화면 안에 온전히 들어온 117장 기준 중앙값 0.0° / p95 2.0°, 초과 1장(`synth_defect_6`)**. 화면 밖으로 잘린 부품은 재측정이 불가해 육안 검수 |
| 편향 잔존도 | 전역 통계 분류 정확도 ≤ 60% | 1.2절 테스트를 정제·전처리 후 데이터로 재실행. **실측: 전처리 후 80.0% → 미달성**, A4 증강 적용 후 재측정 필요 |
| 결함 보존 | 균열·노치가 전처리 후에도 보임 | 결함 유형별 5장씩 전/후 비교 |
| 처리 시간 | 합계 ≤ 6.0ms | 엣지 PC 실측 (1,000프레임 평균·p99) |

## 8. 현장 확인 후 결정할 사항

`dataset_field_survey_checklist.md` 7장의 판단 불가 항목 중 전처리에 영향을 주는 것:

* **실제 너트 규격** (정사각/직사각, 구멍 원형도) → A3 왜곡 이미지 제외 여부
* **도금·녹 품종의 실제 검사 대상 여부** → A2 범위 확장 여부, B1 컬러 채널 유지 여부
* **최소 검출 결함 크기(mm)와 화소 분해능** → B5 입력 크기(256 vs 더 큰 크기) 결정
* **카메라 거리 고정 여부** → 고정이라면 B5 크기 정규화를 단순화할 수 있음
* **실제 배경 재질·조명** → B2 기준값(220), B3 임계값 재조정
