| 항목 | 내용 | 항목 | 내용 |

| **문서 유형** | 하드웨어 부품 구성 보고서 | **작성 일자** | 2026.10.14 |
| **대상 품목** | 금속 사각 너트 (PoC 데이터셋 기준) | **범위** | 검사 유닛 1개 (카메라 + MCU + SBC) |

> **문서 상태**: 구성과 역할 분담은 확정, 예시 모델과 전압·전류 값은 대표 사양입니다. 구매 전 데이터시트로 다시 확인합니다.
> **범위 밖**: 컨베이어 구동, 불량 배출 장치, 라인 PLC는 다루지 않습니다. 본 유닛은 **판정 신호(OK/NG)를 내보내는 것까지** 책임집니다.

## 1. 구성 요약

| 역할 | 부품 | 하는 일 |
| :--- | :--- | :--- |
| **눈** | 카메라 (글로벌 셔터 모노) | 트리거 신호를 받으면 한 장 촬영해 SBC로 영상 전달 |
| **손발** | MCU (XIAO ESP32-S3) | 부품 감지 → 카메라 트리거·조명 점등 → SBC 판정 수신 → OK/NG 신호 출력 |
| **두뇌** | SBC (NVIDIA Jetson Orin Nano) | 전처리 → AI 추론 (PatchCore / YOLO, TensorRT) → 판정을 MCU로 전달 |
| 보조 센서 | 부품 감지 센서, 조도 센서 | 촬영 시점 결정, 조명 상태 감시 |
| 보조 장치 | LED 링 조명, 상태 LED·부저 | 일정한 촬영 조건, 현장 표시 |

**MCU와 SBC를 나누는 이유**: 리눅스(SBC)는 GPIO 응답 시간이 수~수십 ms 흔들립니다. 촬영 시점처럼 시간이 정확해야 하는 일은 MCU가 맡고, 무거운 연산만 SBC가 맡습니다.

## 2. 구성도

```
                    [LED 링 조명] ←(PWM/MOSFET)─┐
                         │                      │
  [부품 감지 센서] ──→ [MCU: XIAO ESP32-S3] ──(트리거)──→ [카메라]
  [조도 센서]   ──(I2C)──→ │    │                           │
                         │    └──→ OK/NG 출력, 상태 LED·부저   │ (MIPI CSI-2 또는 USB)
                         │                                   ↓
                         └────────(USB 시리얼)────────→ [SBC: Jetson Orin Nano]
```

### 신호 흐름 (부품 1개 기준)

1. 부품 감지 센서 → MCU 인터럽트 (채터링 필터, `wokwi/02_entry_sensor`)
2. MCU → 카메라 트리거 펄스 + 조명 점등 (동시에 부품 번호 부여)
3. 카메라 → SBC 영상 전송
4. SBC: 전처리(B1~B8) → 추론 → 판정
5. SBC → MCU: `부품 번호, OK/NG, 이상 점수` (USB 시리얼)
6. MCU → OK/NG 디지털 출력 + 상태 LED

## 4. 부품별 사양과 선정 근거

### 4.1 카메라
| 항목 | 사양 |
| :--- | :--- |
| 센서 | OV9281, **1280×800 모노, 글로벌 셔터**, 화소 3µm |
| 트리거 | 외부 트리거 입력 (MCU GPIO 직결, 전압 레벨은 모델별 확인) |
| 연결 | **MIPI CSI-2 (기본)** — 전송 지연이 낮고 SBC가 직접 받음 / USB(UVC) — 케이블이 길어야 할 때 |

* 체크리스트 [5-2]: 모노크롬 100만 화소급이면 충분.
* 글로벌 셔터라 움직이는 부품도 왜곡 없이 찍힙니다.
* 렌즈: 시야 약 48×30mm (너트 20mm + 회전·위치 여유, 센서 비율 16:10)가 되도록 초점거리와 작동 거리를 정합니다. 이때 해상도는 약 0.0375mm/px(30mm ÷ 800px)로, 균열 폭 0.06~0.14mm가 약 1.6~3.7px로 잡힙니다.
* **주의**: 가장 가는 균열(0.06mm)은 2px에 못 미칩니다. 너트가 0~360° 회전하면 대각선(약 28mm)까지 시야에 들어와야 해서 시야를 더 줄이기도 어렵습니다. 실제 촬영으로 검출 여부를 먼저 확인하고, 부족하면 고해상도 센서를 검토합니다.

### 4.2 MCU — XIAO ESP32-S3
| 항목 | 사양 |
| :--- | :--- |
| 코어 | ESP32-S3 듀얼코어 240MHz, 8MB PSRAM |
| I/O | GPIO 11개 (3.3V), I2C, PWM, 인터럽트 |
| SBC 연결 | 네이티브 USB-CDC (전원 + 시리얼 한 가닥) |

* **맡는 일**: 부품 감지 인터럽트·채터링 필터, 카메라 트리거·조명 동기, 부품 번호 관리, 판정 결과 출력, 상태 표시.
* Wokwi 가상 테스트(`wokwi/01`, `02`)로 핀 배치와 감지 로직을 검증했습니다.
* **GPIO 할당 (예)**

  | 핀 | 신호 |
  | :--- | :--- |
  | D0 | 부품 감지 센서 입력 (인터럽트) |
  | D1 | 카메라 트리거 출력 |
  | D2 | 조명 PWM (MOSFET) |
  | D3 / D6 | OK / NG 출력 (포토커플러 경유) |
  | D4 / D5 | I2C SDA / SCL (조도 센서, XIAO 기본 I2C 핀) |
  | D7 / D8 | 상태 LED 녹·적, D9 부저 |

### 4.3 SBC — Jetson Orin Nano
| 항목 | 사양 |
| :--- | :--- |
| AI 성능 | 최대 67 TOPS (Super 모드), **TensorRT FP16/INT8** |
| 메모리 / 저장 | 8GB / NVMe SSD (불량 이미지 로그) |
| 전원 | 19V DC, 7~25W |
| OS | JetPack (Ubuntu 22.04 기반, PRD 4장과 동일 계열) |

* PRD가 요구한 TensorRT 추론을 그대로 쓸 수 있는 가장 작은 선택지입니다.
* **확장 시**: 카메라 여러 대를 한 장비에서 처리해야 하면 Jetson AGX Orin 또는 RTX 엣지 PC로 올립니다. MCU·카메라 구성은 그대로 둡니다.

### 4.4 보조 센서·장치
| 부품 | 필요한 이유 |
| :--- | :--- |
| **부품 감지 센서** (필수) | 부품이 시야 중앙에 왔을 때만 찍어야 합니다. 금속 반사로 오검출이 생기면 투과형으로 바꿉니다. |
| **LED 링 조명** (필수) | 반유광 금속의 하이라이트([1-2])를 줄이고 촬영 조건을 일정하게 유지합니다. 노광 순간에만 켜서 발열·소비전력을 줄입니다. |
| **조도 센서** (권장) | 조명 노후·외부광 변화를 감지해 경고합니다. 밝기가 변하면 PatchCore 이상 점수가 같이 흔들리기 때문입니다. |
| 상태 LED·부저 | 정상 / 불량 / 장치 이상(SBC 응답 없음 등)을 현장에 표시합니다. |

## 5. 판정 지연 예산 (≤ 35ms)

| 구간 | 예상 시간 | 비고 |
| :--- | :--- | :--- |
| 감지 → 트리거 → 노광 | ≤ 2ms | MCU 인터럽트 |
| 영상 전송 (MIPI CSI-2) | 약 2~5ms | USB 사용 시 약 5~10ms |
| 전처리 (B1~B8) | ≤ 6ms | 개발 PC 약 3ms 실측, Jetson에서 재측정 필요 |
| AI 추론 (TensorRT FP16) | 약 10~20ms (**추정**) | Orin Nano 실측 필요 |
| SBC → MCU → 출력 | ≤ 1ms | USB 시리얼 짧은 메시지 |
| **합계** | **약 21~34ms** | 여유가 작으므로 추론 실측이 최우선 |

* 여유가 부족하면 입력 크기 축소 → INT8 양자화 → 상위 SBC 순서로 대응합니다.

## 7. 한계와 후속 확인 사항

* **추론 시간 실측**: Orin Nano에서 TensorRT 변환 후 5장 표를 갱신합니다.
* **해상도 확인**: 0.06mm 균열이 약 1.6px로 잡히므로, LED 링 조명 아래 실제 촬영으로 검출 가능 여부를 확인합니다 (4.1절).
* **트리거 전압 확인**: 카메라 외부 트리거 입력이 3.3V 로직을 받는지 모델별로 확인합니다.
* **새 조명으로 재수집**: PoC 데이터는 일반 조명 합성 데이터이므로, LED 링 조명 아래에서 정상 이미지를 다시 모아 PatchCore 메모리를 재구성합니다.
* **품목 변경 시**: 렌즈(시야·작동 거리)만 다시 정하고 나머지는 그대로 씁니다.
